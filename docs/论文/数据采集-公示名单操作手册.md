## 2. 三步操作

### 2.1 下载附件

1. 打开上表入口 → 找「名单公示 / 通知公告 / 附件下载」。
2. 下载附件（`.xls` / `.xlsx` / `.pdf` / 网页另存 `.html` 均可）。
3. 全部丢进同一个目录：`data/raw/qual_list/`。

> `.xls`（老格式）本采集器不支持，请用 Excel/WPS 另存为 `.xlsx` 后再导入。

### 2.2 按规范命名（决定自动识别是否生效）

文件名里带上 **资质关键词 + 年份（+批次）** 即可，其余随意：

```
high_tech_2021.csv              → high_tech / 2021 / 批次 2021-1
高新技术企业_2024复核.pdf       → high_tech / 2024 / 批次 2024-1
专精特新小巨人_2024.xlsx         → little_giant / 2024
浙江省科技型中小企业_第2批_2025.csv → tech_sme / 2025 / 批次 2025-2
```

识别不出时会跳过并提示，可用参数显式指定：
`--qual-type high_tech --year 2024 --batch 2024-1`

> 坑：文件名同时含「专精特新」和「小巨人」时，按「小巨人」处理（层级更高）。

### 2.3 导入数据库

```bash
# 0) 首次使用先建库（已有则跳过）
.venv/Scripts/python.exe -m src.data.db --init

# 1) 先预览，确认列名识别对了、没有把「合计」当企业
.venv/Scripts/python.exe -m src.data.collect_pool --dir data/raw/qual_list --dry-run

# 2) 正式导入（批量模式，自动推断类型/年份/批次）
.venv/Scripts/python.exe -m src.data.collect_pool --dir data/raw/qual_list

# 3) 单文件显式指定（推荐用于高新关键两份）
.venv/Scripts/python.exe -m src.data.collect_pool \
    --file data/raw/qual_list/high_tech_2021.csv \
    --qual-type high_tech --year 2021 --batch 2021-1 --issuer "浙江省高新技术企业认定管理机构"

# 4) 只落 ods、暂不生成主数据（想人工核对原始行时）
.venv/Scripts/python.exe -m src.data.collect_pool --dir data/raw/qual_list --no-promote

# 5) 自检（不碰正式库，用合成样例跑端到端）
.venv/Scripts/python.exe -m src.data.collect_pool --selftest
```

可选：直接抓网页（`--fetch-url`），存 HTML 并列出附件链接。政务站常有人机校验，**附件建议仍人工下载**：

```bash
.venv/Scripts/python.exe -m src.data.collect_pool \
    --fetch-url "https://zj87.jxt.zj.gov.cn/zlzq/web/views/article/news/detail.html?id=288178"
```

## 3. 导入后校验（必做）

```bash
# 结构体检 + 覆盖度
.venv/Scripts/python.exe -m src.data.db --verify
```

覆盖度视图直接查：

```sql
SELECT * FROM v_data_coverage;                       -- 各对象行数
SELECT year, qual_type, COUNT(*) FROM fact_qualification GROUP BY 1,2 ORDER BY 1,2;
SELECT COUNT(DISTINCT enterprise_id) FROM fact_qualification WHERE qual_type='high_tech';
-- 关键：2021 认定 & 2024 复核 的交集企业数（决定主标签样本量）
SELECT COUNT(*) FROM fact_qualification a
JOIN fact_qualification b USING(enterprise_id)
WHERE a.qual_type='high_tech' AND a.year=2021
  AND b.qual_type='high_tech' AND b.year=2024;
```

**验收标准**

| 项 | 目标 |
|---|---|
| 高新技术企业（2021 认定 ∩ 2024 复核） | **≥ 2000 家**（标签样本下限，低于 1500 需扩大名单来源） |
| 全部资质去重企业数 | ≥ 8000 家 |
| 覆盖年份 | 至少 2021–2025，能往回补到 2019 更好 |
| 采集日志 | 每份文件 2 条（parse + build），`file_sha256` 非空 |

## 4. 已知坑与应对

| 现象 | 原因 / 处理 |
|---|---|
| 提示「无法识别资质类型」 | 文件名缺关键词 → 加 `--qual-type` |
| 提示「未识别到企业名列」 | 表头非标准（如“申报主体”）→ 后续可加 `--name-col`；或手动改表头为「企业名称」 |
| 企业数明显偏少 | 名单被拆成多个 sheet/多个地市文件 → 全下全导；或附件是扫描件 PDF（需 OCR，本脚本不处理） |
| 出现奇怪的短名/机构名 | 清洗规则已剔除 <4 字与纯数字行，但「研究院/中心」类会保留，属正常 |
| 同名不同写法 | 规范化名一致 → 自动合并，并在 `dim_enterprise_alias` 留痕，请抽查确认没有误合并 |
| 「公示」≠「最终认定」 | 拟入库公示后可能有异议剔除。**论文须声明**：以公示名单为近似，复核名单为结果 |
| 数据翻倍 | 不会。同一公告批次、同一企业名均幂等，可放心重跑 |
