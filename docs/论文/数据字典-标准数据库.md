# 标准数据库 · 数据字典与设计说明 v1.0

> **项目**：融合技术要素与成长轨迹的中小科技企业信用智能评估方法构建
> **数据库**：`data/db/zjtech_credit.db`（SQLite 3.37+，STRICT tables）
> **Schema 版本**：v1.0　｜　**建立日期**：2026-10-14
> **DLL 源码**：`src/data/schema.sql`　｜　**管理脚本**：`src/data/db.py`
> **结构清单**：`configs/db_schema_manifest.json`（自动生成，供版本比对）
> **上游口径**：`docs/特征工程字典.md`、`docs/数据替代方案-开源数据路线.md`
> **主责**：吕键（后端 / 数据管道）；指标口径确认 张丽晶；模型消费口径 施汶邑

## 1. 为什么是这套设计

| 设计选择 | 理由 |
|---|---|
| **SQLite（stdlib）** | 零新依赖 —— 队伍严格锁版本，任何新包都是可复现性风险。单文件、可直接拷贝/同步网盘，成员拿到即用 |
| **STRICT tables** | SQLite 默认是弱类型（能把字符串塞进 INTEGER 列）。STRICT 开启真实类型校验，这是"标准数据库"的底线 |
| **六层分层（meta/ods/dim/fact/dws/ads）** | 原始层与业务层隔离：数据源换了只改 ods 层，模型层不动。这直接回应立项"多源异构数据融合"的工程要求 |
| **代理键不依赖统一社会信用代码** | 公开名单不含信用代码（已验证）。用 `ENT+md5(规范化名)` 确定性生成，名称规范化后同一企业永远得到同一 ID |
| **枚举全部 CHECK 约束** | 口径漂移是数据质量问题第一来源。`qual_type`、`patent_type`、`split` 等一律固化，自由文本写不进去 |
| **标签单独成表（`ads_label`）** | 主任务（资质存续）与对照任务（MSME 违约）同表不同 `label_task`，避免"一个数据集一个脚本"的碎片化 |
| **图结构入库（`ads_graph_*`）** | 图谱不必每次从 SQL 现场拼，节点边物化后 PyG 直接读，且年度切片天然支持时序图 |

## 2. 分层架构与数据流

```
 数据源（全部免费）
 ┌──────────────────────────────────────────────────────────────┐
 │ 浙江省三层公示名单   Google Patents/CNIPA   Kaggle MSME/SBA  │
 │        (网页/PDF)          (BigQuery/批量包)      (开放数据集) │
 └───────────┬────────────────────┬──────────────────┬──────────┘
             ↓                    ↓                  ↓
 ┌──────────────────────────────────────────────────────────────┐
 │ ① ods 原始落库层：保持与来源同构，不做业务判断                  │
 │    ods_qual_notice / ods_qual_company_raw / ods_patent_raw    │
 └───────────────────────────┬──────────────────────────────────┘
                             ↓ 解析·规范化·名称消歧（log_match 留审计轨迹）
 ┌──────────────────────────────────────────────────────────────┐
 │ ② dim 维度主数据：去重后的标准实体                             │
 │    dim_enterprise / dim_enterprise_alias / dim_qual_type      │
 │    dim_ipc / dim_inventor                                     │
 └───────────────────────────┬──────────────────────────────────┘
                             ↓ 关联事实
 ┌──────────────────────────────────────────────────────────────┐
 │ ③ fact 业务事实层                                              │
 │    fact_qualification → fact_qualification_event（晋级序列）   │
 │    fact_patent + bridge_patent_ipc / bridge_patent_inventor    │
 │    fact_patent_citation（知识扩散）fact_funding_event（定增）  │
 └───────────────────────────┬──────────────────────────────────┘
                             ↓ 按 企业×年度 汇总
 ┌──────────────────────────────────────────────────────────────┐
 │ ④ dws 特征汇总层（15 个指标的落地处）                          │
 │    dws_tech_feature（技术要素 7 项）                           │
 │    dws_growth_feature（成长轨迹 6 项 + 资质晋级代理）           │
 │    dws_fusion_feature（融合特征 2 项）                         │
 └───────────────────────────┬──────────────────────────────────┘
                             ↓ 组宽表 + 打标签 + 物化图
 ┌──────────────────────────────────────────────────────────────┐
 │ ⑤ ads 应用层：模型与图谱的唯一入口                             │
 │    ads_label（标签）ads_model_dataset（含 split，冻结切分）     │
 │    ads_graph_node / ads_graph_edge（PyG 消费）                 │
 └──────────────────────────────────────────────────────────────┘

 旁路：meta 层（meta_data_source 数据源登记 / meta_ingest_log 采集日志含文件哈希）
       —— 保证任何一次实验都能追溯到具体的数据版本与来源
```

**铁律**：模型的输入**只能**来自 `ads_model_dataset`。任何绕过它直接在 fact 层捞特征的做法，都会破坏跨模型可比性。

## 4. 核心表字段字典

### 4.1 `dim_enterprise` —— 企业主表（全库锚点）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `enterprise_id` | TEXT | PK | `ENT` + md5(规范化名)[:12] 大写；确定性生成，名称规范化后稳定 |
| `name_display` | TEXT | NOT NULL | 展示名（取最近一次公示原文） |
| `name_norm` | TEXT | NOT NULL, UNIQUE | 规范化名（去省市前缀/括号备注/全半角统一） |
| `credit_code` | TEXT | 可空 | 统一社会信用代码（公开名单未提供，待补） |
| `region_code` | TEXT | | 区域码，浙江 `330000` |
| `region_name` | TEXT | | 辖区名（原文） |
| `enterprise_type` | TEXT | CHECK | `tech_sme`/`high_tech`/`specialized`/`little_giant`/`multi`/`unknown` |
| `first_qual_year` | INTEGER | | 首次进入任一名单的年份 |
| `last_qual_year` | INTEGER | | 最近一次在榜年份 |
| `max_qual_rank` | INTEGER | | 历史最高资质层级（晋级序列终点，1–4） |
| `is_listed` | INTEGER | CHECK 0/1 | 是否上市 |
| `stock_code` | TEXT | | AKShare 代码（若上市） |
| `patent_cnt` | INTEGER | | 缓存：已匹配专利数（DWS 回填） |
| `created_at` / `updated_at` | TEXT | | 审计时间戳 |

### 4.2 `fact_patent` —— 专利事实表（技术要素的原料）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `patent_id` | TEXT | PK | = 公开号（如 `CN110123456A`） |
| `app_no` | TEXT | | 申请号 |
| `title` / `abstract` | TEXT | | 标题 / 摘要（摘要供 SciBERT 向量化） |
| `app_date` / `app_year` | TEXT / INT | | 申请日 / **申请年（时间维主键）** |
| `pub_date` / `grant_date` / `grant_year` | TEXT / INT | | 公开日 / 授权日 / 授权年 |
| `patent_type` | TEXT | CHECK | `invention`（发明）/`utility`（实用新型）/`design`（外观设计） |
| `legal_status` | TEXT | | `granted`/`pending`/`expired`/`withdrawn` |
| `is_granted` | INTEGER | CHECK 0/1 | 是否已授权（授权率计算用） |
| `country_code` | TEXT | NOT NULL, 默认 `CN` | 国别 |
| `enterprise_id` | TEXT | FK → dim_enterprise | 匹配到的企业（未匹配为 NULL） |
| `assignee_raw` | TEXT | | 原始申请人字符串（原文保留） |
| `assignee_addr_raw` | TEXT | | 原始地址（区域筛选依据） |
| `match_confidence` | REAL | CHECK 0–1 | 匹配置信度 |
| `match_method` | TEXT | CHECK | `exact`/`alias`/`fuzzy`/`inventor_anchor`/`manual` |

| 字段 | 类型 | 约束 | 说明 |

| `is_renewal` | INTEGER | CHECK 0/1 | 是否复评/重新认定 |

### 4.4 `dws_tech_feature` —— 技术要素特征（对应字典 3.1–3.7）

**粒度**：企业 × 年度　**主键**：`(enterprise_id, stat_year)`

| 字段 | 字典编号 | 说明 |
|---|---|---|
| `inv_patent_ratio` | 3.1 | 发明专利占比 = 发明申请量 / 申请总量 |
| `grant_rate` | 3.2 | 授权率（按申请年对齐，剔除 `pending`） |
| `patent_citation` | 3.3 | 近 5 年被引总数（原始计数见 `n_patent_cited`） |
| `tech_breadth_ipc_class` | 3.4 | 技术广度·IPC 小类覆盖数 |
| `tech_breadth_entropy` | 3.4 | 技术广度·Shannon 熵 |
| `patent_triple_score` | 3.5 | 专利三值评分（SciBERT + 被引/同族/权利要求数） |
| `core_staff_stability` | 3.6 | 核心人员稳定性（以发明人界定：1 − 年流失率） |
| `rd_intensity` | 3.7 | 研发投入（替代口径 = 研发人员占比） |
| `rd_intensity_flag` | — | **口径标注**：`reported`/`proxy`/`missing`（敏感性分析用） |
| `n_patent_app` / `n_patent_grant` | — | 申请总数 / 授权总数 |
| `n_patent_invention` / `n_patent_utility` / `n_patent_design` | — | 三类专利计数 |
| `n_patent_cited` / `n_inventor` / `n_ipc_subclass` | — | 被引专利数 / 发明人数 / IPC 小类数 |
| `n_patent_collab` | — | 合作申请数（≥2 申请人 → 产业链协作网络原料） |
| `first_app_year` / `computed_at` | — | 首次申请年 / 计算时间戳 |

### 4.5 `dws_growth_feature` —— 成长轨迹特征（对应字典 4.1–4.6）

**粒度**：企业 × 年度　**主键**：`(enterprise_id, stat_year)`

| 字段 | 字典编号 | 说明 |
|---|---|---|
| `rev_cagr` | 4.1 | 3 年营收 CAGR（替代口径，见 `rev_cagr_flag`） |
| `emp_cagr` | 4.2 | 3 年员工数 CAGR |
| `patent_cagr` | 4.3 | 3 年专利申请 CAGR |
| `funding_to_last_val` | 4.4 | 本轮融资额 / 上轮投后估值（**非上市缺失 → 用 `qual_rank_delta` 代理**） |
| `m_funding` / `m_team` / `m_cert` / `m_cite` | 4.5 | 四类里程碑虚拟变量（`m_cert` 由名单差分免费产出） |
| `investor_prestige` | 4.6 | 投资机构知名度等级（1 头部 VC … 4 个人天使） |
| `rev_cagr_flag` | — | 口径标注：`reported`/`proxy`/`missing` |
| `qual_rank` | **新增 A1** | 当年资质层级（1–4） |
| `qual_rank_delta` | **新增 A1** | 当年层级变化（晋升 +n / 失效 −n） |
| `qual_upgrade_cum` | **新增 A1** | 累计晋级次数 |
| `ever_fail_review` | **新增 A1** | 是否曾有复核未通过 |

### 4.6 `ads_label` —— 标签表（多任务多队列）

**主键**：`(enterprise_id, label_task, cohort_year)`

| 字段 | 说明 |
|---|---|
| `label_task` | `qual_survival`（**主任务**）/`msme_default`（对照）/`sba_default`（稳健性）/`survival_risk`（前瞻） |
| `cohort_year` | 观察队列起始年（= 特征窗口终点，2021 等） |
| `label_value` | 0 / 1 |
| `label_name` | 中文名（论文用），如「科技资质存续失败」 |
| `observation_start` / `observation_end` | 特征窗口 / 观察窗口 |
| `definition_ver` | **标签定义版本**（口径变更必须升版） |
| `n_events` | 关联事件数 |

> **主标签口径**：2021 年高新认定队列 → 2024 年复核名单；未出现 = 1。特征窗口限定 2019–2021，无泄漏。

### 4.7 `ads_model_dataset` —— 建模宽表（模型唯一入口）

**主键**：`(enterprise_id, dataset_ver, label_task, cohort_year)`

- 特征列：与 `dws_*` 同名列直接摊平（技术要素 8 + 计数 6 + 成长轨迹 8 + 资质代理 3 + 融合 3 ≈ 28 列）
- `label`：0/1
- `split`：`train`/`val`/`test`/`excluded`（**CHECK 约束，一次性写入并冻结**）
- `split_protocol`：切分协议文字描述（保证跨模型可比）
- `dataset_ver`：数据集版本（如 `ds_v1.0`）
- `built_at`：生成时间戳

### 4.8 `ads_graph_node` / `ads_graph_edge` —— 图结构

节点（`node_type` ∈ `enterprise`/`patent`/`ipc`/`inventor`，含 `time_slice` 年度切片）：

| 字段 | 说明 |
|---|---|
| `node_id` | 对应各维表主键 |
| `time_slice` | 年度切片 |
| `display_name` | 展示名（企业名 / 专利标题 / IPC 名 / 发明人名） |

边（`edge_type` 四类）：

| `edge_type` | 方向 | 含义 | 是否外部独立信息 |
|---|---|---|---|
| `files_patent` | enterprise → patent | 企业申请专利 | 否（来自样本池匹配） |
| `belongs_ipc` | patent → ipc | 专利归属技术领域 | 是（IPC 分类体系） |
| `co_inventor` | enterprise ↔ enterprise | **共有发明人（人才流动）** | **是（关键增益来源）** |
| `cites` | enterprise → enterprise | 专利被引（知识扩散） | **是** |
| `qualifies` | enterprise → enterprise | 同批次资质共现 | 是 |

> `co_inventor` 与 `cites` 是纯外部独立信息 —— 原信贷面板的图增益只有 +0.013 AUC，正是因为它的边全从同一批特征派生。这两类边是本次图增益的预期突破点。

## 6. 命名与口径约定（团队必须遵守）

1. **代理键**：企业 `ENT`+12hex、发明人 `INV`+10hex、专利 = 公开号。**禁止**用名称做外键；`name_norm` 只用于唯一约束与匹配。
2. **日期/时间**：日期一律 `TEXT 'YYYY-MM-DD'`；年月 `TEXT 'YYYY-MM'`；年份 `INTEGER`。
3. **枚举**：全部由 CHECK 约束固化。新增枚举值必须改 schema 并升版本。
4. **缺失**：数据库层**不使用哨兵值**（-1/-999），一律 NULL；哨兵值只在特征工程阶段引入且必须有记录。
5. **口径存疑字段**：`rd_intensity`、`rev_cagr` 等替代口径，必须同步填 `*_flag` 字段；下游敏感性分析依赖它。
6. **溯源**：任何进入 fact 层的行必须能追回 ods 层（`raw_id`），ods 行必须能追回 `meta_ingest_log`（含文件 SHA256）。
7. **外键**：SQLite 默认关闭外键校验，**所有连接必须执行 `PRAGMA foreign_keys = ON`**（`src/data/db.py::connect()` 已封装，请勿绕过）。

## 7. 常用查询示例

```sql
-- ① 企业画像速览
SELECT * FROM v_enterprise_profile WHERE max_qual_rank >= 3 LIMIT 20;

-- ② 年度专利产出（技术要素原始来源）
SELECT stat_year, n_app, n_grant, n_inv FROM v_patent_yearly
WHERE enterprise_id = 'ENTxxxxxxxxxxxx' ORDER BY stat_year;

-- ③ 资质履历（含晋级/失效）
SELECT * FROM v_qual_history WHERE enterprise_id = 'ENTxxxxxxxxxxxx';

-- ④ 样本规模与标签分布（建模前必看）
SELECT label_task, cohort_year, label, COUNT(*) n
FROM ads_model_dataset GROUP BY label_task, cohort_year, label;

-- ⑤ 图规模（四类边分别多少）
SELECT edge_type, time_slice, COUNT(*) n FROM ads_graph_edge
GROUP BY edge_type, time_slice ORDER BY edge_type, time_slice;

-- ⑥ 匹配质量自查（论文要写匹配准确率）
SELECT method, decision, COUNT(*) n, ROUND(AVG(score),3) avg_score
FROM log_match GROUP BY method, decision;

-- ⑦ 15 指标缺失率体检（决定哪些企业剔除）
SELECT COUNT(*) n,
       ROUND(AVG(inv_patent_ratio IS NULL), 3) miss_inv_ratio,
       ROUND(AVG(patent_citation  IS NULL), 3) miss_citation,
       ROUND(AVG(rd_intensity     IS NULL), 3) miss_rd
FROM dws_tech_feature WHERE stat_year = 2021;
```
