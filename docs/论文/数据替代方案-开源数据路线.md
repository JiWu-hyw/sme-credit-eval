> **决策背景**：浙江信贷面板提供方的 P0 缺口（userid 映射键、x21–x200 字段字典、label 口径）确认不可得后，本项目改用**全公开数据源**重建数据体系。

## 1. 为什么转开源路线（三条实测依据）

来自 `docs/真实数据摸底报告.md` 与 `docs/实验结果报告-基线SHAP与GAT.md` 的实测结论：

1. **原面板 99% 的 SHAP 贡献落在语义未知的 x21–x200**，x1–x20 只占 1%，top-20 中语义已知特征为 0 个 → 可解释性叙事被字段字典卡死，且字典拿不到。
2. **面板区分度天花板 ≈0.59**（行级 AUC 0.595，置换对照噪声地板 0.477），**企业级信号直接消失**（0.47）→ 该面板本身不含有"技术要素"，也撑不起"科技企业信用"的定位。
3. **图增益仅 +0.013 AUC** → 因为边全从同一批特征派生，无外部新信息。立项书说的"多源异构数据融合壁垒"已被实证，而破壁需要的正是外部独立数据。

**这三条反而成了新方案最硬的立项论证**：传统行为信贷数据不足以评估科技企业信用；必须引入独立来源的技术要素数据。开源路线不是退而求其次，是把"动机"变成"解法"。

## 3. 方案 A（主线）：浙江科技企业"资质动态"面板

### 3.1 样本池构建

**三层名单叠加去重**，得到浙江科技企业母池：

| 层 | 来源 | 作用 |
|---|---|---|
| L1 科技型中小企业 | 2021–2026 各批次公示 | 广覆盖母池（多数无专利） |
| L2 高新技术企业 | 2021–2025 备案公告 | 核心样本（有研发活动的强信号） |
| L3 专精特新 | 2023–2026 各市公示 | 成长性锚点（梯度晋级序列） |

**操作要点**：
- 公示附件格式混杂（网页表格 / PDF / docx），需为每种写解析器；优先用**浙江省企业之家网**的网页版名单（结构化最好）。
- 统一社会信用代码一般不在公示中 → **以企业全名为主键**，配套做规范化（去省市前缀、去括号备注、全半角统一）。
- 每批公示记录"批次号 + 公示日期 + 企业名 + 辖区"，构成面板的行。
- 预估规模：L1+L2+L3 去重后 **6–10 万家**；其中能匹配到 ≥1 件专利的子集预计 **1.5–3 万家**（建模用这个子集，样本量是原信贷面板 1,714 家的 10 倍以上）。

### 3.2 专利数据获取（两条路线，路线一优先）

**路线一（推荐）：BigQuery 公开数据集一次筛选**

Google Patents Public Datasets 以 BigQuery 公开表形式提供（`google_patents_research.publications`），中国专利全量在内，每月有免费查询额度。对 3–5 万家名单不需要逐家查询——**按申请人地址一次筛出浙江**：

```sql
-- 一次性把中国专利中申请人含浙江的记录导出（本地再与企业名单匹配）
SELECT publication_number, filing_date, grant_date,
       assignee, assignee_address, inventor, ipc,
       citation, legal_status, country_code
FROM `google_patents_research.publications`
WHERE country_code = 'CN'
  AND (assignee_address LIKE '%Zhejiang%' OR assignee_address LIKE '%杭州%' ...)
```

- 单次全表/区域扫描约数十 GB，在每月免费额度内可完成 1–2 次，**务必规划查询次数**（见 §7 风险）。
- 导出到 GCS 或直接下载为 parquet/csv，交给 `src/data/` 做本地匹配。
- 需 Google 账号 + 开通 BigQuery（免费层，绑卡验证但不扣费）。

**路线二（补充/增量）：CNIPA 官方批量下载**

注册 ipdps.cnipa.gov.cn 后按数据种类下载中国专利基础数据包（含公布/授权/法律状态）。适合做**近期增量补齐**（BigQuery 快照滞后时），以及论文中声明"官方数据源"背书。数据包较大，建议按季度增量包下载。

**GitHub 800 万条集**作为第三来源备查（仅覆盖 2020–2025，HTML 格式，解析成本高，非首选）。

### 3.3 标签设计（本方案的核心创新点）

原面板的 label 拿不到口径，改用**完全公开、可复现、带时间维**的标签：

> **标签定义：科技资质存续失败（Tech-Qualification Survival Failure）**
> 高新技术企业资格有效期 3 年。以 **2021 年批次认定**的企业为观察队列，观察其是否出现在 **2024 年重新认定**名单中：未出现 = 标签 1（存续失败），出现 = 标签 0。
> 特征窗口严格限定在 **2019–2021**（认定之前），标签窗口 2024，无泄漏。

**为什么这个标签站得住**：
- 高新复核是**真实的官方审查**（知识产权、研发费用、科技人员占比、高新收入占比四项硬指标），未通过就是经营/合规恶化的公开信号——不是人造标签。
- 自带时间维，天然支持"用历史预测未来"的叙事，匹配项目"成长轨迹"主题。
- 多批次可滚动构造多个观察队列（2019→2022、2020→2023、2021→2024），缓解单队列样本偏差。

**对照标签**：Kaggle MSME 的信贷违约 0/1（见 §5），用于回答"资质存续失败与信贷违约是否同源"——若两个标签下技术要素的重要性排序一致，说明技术要素是跨口径的通用风险信号，这是论文的一个强论点。

**论文命名纪律**：主实验标签必须写"科技资质存续失败"，不得写成"信用违约"；两者关系作为独立分析节。

### 3.4 特征体系（复用《特征工程字典》编号，全部可由公开数据算出）

| 字典编号 | 指标 | 本方案数据来源 | 状态 |
|---|---|---|---|
| 技术要素 T1 | 发明专利申请量（近 3 年） | 专利匹配 | ✅ 可算 |
| T2 | 发明专利占比（发明/实用新型+外观） | 专利类型字段 | ✅ |
| T3 | 授权率（授权数/申请数，滞后窗） | 法律状态 | ✅ |
| T4 | 被引次数（前向引用） | citation 字段 | ✅ |
| T5 | 技术广度（IPC 小类数/熵） | IPC 字段 | ✅ |

### 3.5 异质图设计（四类实体，落在原设计六类实体的核心层）

```
节点：
  enterprise  企业        （样本池企业）
  patent      专利        （publication_number）
  ipc         技术领域    （IPC 小类，取前 4 位）
  inventor    发明人      （去重后的发明人姓名+地址组合，公开专利字段）

边：
  enterprise -[申请]-> patent            （assignee 匹配）
  patent     -[属于]-> ipc               （IPC 分类）
  enterprise -[共有发明人]-> enterprise  （人才流动网络：同一发明人服务于两家企业）
  enterprise -[被引]-> enterprise        （知识扩散：A 的专利被 B 引用，滞后窗）

时间切片：按年切片（2019/2020/2021/2022/2023/2024），节点特征取当年快照
```

- 这张图直接复用 `src/graph/panel_graph.py` 的接口模式（节点类型 + 边类型 + `to_hetero`），施汶邑把 record/company/cluster 三类换成 enterprise/patent/ipc/inventor 四类即可。
- **人才流动边**是纯外部信息（原面板最缺的东西），预期图增益显著高于之前的 +0.013——这本身就是论文的对照实验。

### 3.6 建模：完全复用现有 pipeline

| 现有模块 | 复用方式 |
|---|---|
| `src/data/preprocess.py` | 分组切分（按企业）、缺失填充、缩尾、Z-score 全部沿用，输入换成新特征表 |
| `src/model/metrics.py` | AUC/KS/Acc/P/R/F1 + best-F1 阈值，不动 |
| `src/model/baseline.py` | LR/XGBoost + GroupKFold + 置换对照，直接跑 |
| `src/model/gat_panel.py` | GAT 结构不变，图数据源换成 §3.5 的四类实体图；无图 MLP 对照保留 |
| `src/explain/global_shap.py` | SHAP 全局解释直接可用——**且这次特征全部有业务语义**，可解释性叙事完整闭合 |
| `run_demo.py`（合成图） | 保留作架构验证腿，不动 |

## 4. 方案 B（对照）：公开信用数据集

### 4.1 MSME Credit Data by 30S-CR（主对照）

- 1,707 家中国中小微企业、87 特征、0/1 违约标签、附官方数据说明文件，CC BY-NC 4.0（学术研究可用）。

- 用途：大规模样本下的基准对比 + 时间外推验证（按 ApprovalFY 切训练/测试）。
- 定位：稳健性附录，证明方法不依赖单一数据集。

## 6. 融资维度的替代方案（诚实声明）

中国初创企业融资事件**无免费公开源**（Crunchbase 2025 年已取消免费 API；IT 桔子/清科均付费；SEC EDGAR 仅覆盖美国私募）。替代设计：

1. **主替代**：资质晋级序列（科技型→高新→专精特新→国家级小巨人）本身是政策性金融信号，获得认定通常伴随授信/补贴/贴息——在浙江语境下是比融资额更贴近"政策性信用"的变量。
2. **补充替代**：专利合作申请网络（企业间共同申请）作为"资本-技术协同"的弱代理。
3. **上市公司子集**：用 AKShare 拉取浙江科技上市公司的定增/可转债/IPO 公告，构造真实融资事件，做融资力预测模块的**方法验证**（小样本但标签真实）。
4. **论文声明**：在数据局限节明确写出"非上市中小企业融资数据不可公开获取，融资力预测以方法设计+上市公司子集验证呈现"，这是合规且诚实的处理。

## 8. 风险清单与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **企业名称与专利申请人不匹配**（同名、更名、简称） | 专利特征缺失/错配 | 三级匹配置信（精确/高置信模糊/低置信），只保留前两级；抽样人工校验 100 家估计准确率并写入论文 |
| **BigQuery 超额费用** | 预算外支出 | 先用 `LIMIT` + 分区字段试查询评估扫描量；单月控制在 1–2 次大查询；超额则切 CNIPA 批量下载 |
| **标签稀疏**（2021 高新认定企业仅数千家） | 有效样本不足 | 滚动三个观察队列合并；补充"科技型中小企业连续两年缺席"作弱标签队列 |
| **高新未通过是主动放弃**（并购/转型而非恶化） | 标签噪声 | 论文做敏感性分析：剔除名单中当年有并购/更名迹象的样本（从专精特新晋级反向排除） |
| **名单附件格式混杂** | 抓取工期超支 | 优先网页版结构化名单；PDF/docx 只作补充；吕键 2 周内交付解析器 |
| **发明人隐私顾虑** | 合规 | 只用公开专利字段的发明人姓名，论文中做去标识化处理并声明 |
| 发明人同名导致人才流动边噪声 | 图结构误差 | 人才流动边用"姓名+地址组合"匹配，且只统计 ≥2 次共现的边 |
