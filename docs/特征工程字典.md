# 特征工程字典（初稿 v0.1）

> **项目**：融合技术要素与成长轨迹的中小科技企业信用智能评估方法构建
> **所属模块**：模块一（多源异构数据采集与预处理）的输入契约
> **主责**：袁雪茹（负责人 / 金融统筹）
> **状态**：初稿，待数据组（吕键）与校验组（张丽晶）确认后冻结
> **日期**：2026-10-07
> **消费方**：T12 标准化企业级特征表 schema → T20 图谱 → T30 模型

## 1. 目的与口径约定

本字典定义信用评估模型使用的全部特征，是"数据 → 图谱 → 模型 → 解释 → 预测"链路的第一道接口契约。任何指标改动都须先更新本字典，再同步下游 schema，**禁止口头改口径**。

**三大类**：
- **技术要素**：企业"硬科技"实力的静态与半静态刻画（专利 / 研发 / 团队）。
- **成长轨迹**：企业随时间演化的动态能力（融资 / 里程碑 / 规模增长）。
- **融合特征**：技术要素与成长轨迹交叉派生，刻画"技术能否转化为增长"。

**统一约定**：
- 时间粒度：**年度为主**，关键指标补季度点；里程碑用事件标记（见 §4.5）。
- 优先级：**P0**=模型核心必取；**P1**=重要、争取获取；**P2**=锦上添花、视数据可得性。
- 缺失策略：P0 缺失超 30% 的企业从训练集剔除；P1/P2 缺失用组内中位数填充（统一在 T11 预处理流水线处理）。

## 3. 技术要素类（7 项）

### 3.1 发明专利占比  `inv_patent_ratio` ｜ P0
- **定义**：企业发明专利申请量占全部专利申请量的比例，反映技术"含金量与门槛"。
- **口径**：`发明专利申请数 / 专利申请总数`（发明、实用新型、外观设计三类合计）。
- **数据来源**：CNIPA。
- **获取可行性**：高，官方可检索；批量需授权。
- **优先级**：P0（区分"真研发"与"外观型"企业）。

### 3.2 专利授权率  `grant_rate` ｜ P0
- **定义**：已授权专利占申请专利的比例，反映技术质量与审查通过能力。
- **口径**：`授权专利数 / 申请专利数`（按申请年对齐，剔除尚在审查中的未决项）。
- **数据来源**：CNIPA。
- **获取可行性**：高。
- **优先级**：P0。

### 3.3 专利被引（技术影响力）  `patent_citation` ｜ P1
- **定义**：企业专利被后续专利引用的次数，衡量技术的前沿性与外溢价值。
- **口径**：`近 5 年企业专利被引总数`（或加权的被引-年代衰减值）。
- **数据来源**：Incopat / 万方 / Google Patents。
- **获取可行性**：中，需付费库或外部接口；中小科技企业样本被引普遍稀疏，需做零值处理。
- **优先级**：P1（强信号但可得性差）。

### 3.4 技术广度  `tech_breadth` ｜ P1
- **定义**：企业技术布局的跨领域分散程度，避免"单点依赖"风险。
- **口径**：`专利 IPC 大类（A~H 部）覆盖数` 或 `Shannon 熵`（基于 IPC 小类分布）。
- **数据来源**：CNIPA + IPC 分类字典。
- **获取可行性**：高（IPC 自带分类）。
- **优先级**：P1。

### 3.5 专利三值评分  `patent_triple_score` ｜ P1
- **定义**：对单件专利从"质量—价值—战略"三维打分的聚合，替代人工评审。
- **口径**：用 SciBERT 将专利摘要向量化，结合被引/家族规模/权利要求数，训练轻量打分器（或无监督加权）；企业层面取均值 / Top-k 均值。
- **数据来源**：CNIPA 摘要 + SciBERT（`src/data/load_scibert.py`）。
- **获取可行性**：中，依赖 T11 文本向量化流水线落地。
- **优先级**：P1（体现本项目"语义建模"创新点）。

### 3.6 核心人员稳定性  `core_staff_stability` ｜ P1
- **定义**：核心技术 / 研发人员的任职持续度，反映团队抗风险能力。
- **口径**：`近 3 年核心研发人员平均任职时长` 或 `1 - 年流失率`（核心人员以发明人 / 高管名单界定）。
- **数据来源**：企查查（任职变更）+ 招聘平台（团队规模）。
- **获取可行性**：中，核心人员界定需业务规则。
- **优先级**：P1。

### 3.7 研发投入  `rd_intensity` ｜ P0
- **定义**：企业在研发上的资源投入强度。
- **口径（首选）**：`研发费用 / 营业收入`；（**替代口径**，公开数据缺失时）：`研发人员占比 = 研发人员数 / 员工总数`。
- **数据来源**：税务 / 财报（首选，非公开）；招聘平台（替代）。
- **获取可行性**：低（首选口径难获取）→ **默认采用替代口径**，并在校验组（T13）做敏感性说明。
- **优先级**：P0（但需用替代口径落地）。

## 4. 成长轨迹类

> 说明：复合增长率统一用 `CAGR = (End/Start)^(1/n) - 1`，n 为年数；缺失首尾年份时退化为相邻年增速。

### 4.1 营收复合增长率  `rev_cagr` ｜ P0
- **定义**：企业营收的年均增速，核心成长信号。
- **口径**：3 年营收 CAGR。
- **数据来源**：财报 / 企查查（营收披露）。
- **获取可行性**：中（中小企业披露不全）→ 与 `rd_intensity` 同理需替代/估算。
- **优先级**：P0。

### 4.2 员工复合增长率  `emp_cagr` ｜ P1
- **定义**：团队规模的扩张速度。
- **口径**：3 年员工数 CAGR（社保 / 招聘平台）。
- **数据来源**：招聘平台 / 公开社保。
- **获取可行性**：中。
- **优先级**：P1。

### 4.3 专利复合增长率  `patent_cagr` ｜ P1
- **定义**：技术产出的增速，与技术要素类呼应。
- **口径**：3 年专利申请 CAGR。
- **数据来源**：CNIPA。
- **获取可行性**：高。
- **优先级**：P1。

### 4.4 新获融资额与上轮估值比  `funding_to_last_val` ｜ P0
- **定义**：本轮融资规模相对上轮估值的放大倍数，反映资本认可度与估值健康度。
- **口径**：`本轮融资额 / 上轮投后估值`（首轮用绝对额 + 行业基准归一）。
- **数据来源**：企查查（融资事件）。
- **获取可行性**：中（融资数据覆盖不均）。
- **优先级**：P0。

### 4.5 里程碑虚拟变量  `milestone_flags` ｜ P1
- **定义**：将关键事件转为 0/1 标志，支撑图谱"里程碑事件标记"（T22）。
- **口径**：四类标志位——
  - `m_funding`：期间发生融资；
  - `m_team`：核心团队变动（高管 / 发明人离职）；
  - `m_cert`：获取资质（高新企业 / 专精特新 / 体系认证）；
  - `m_cite`：产生高影响力引用（被引进入领域 Top 1%）。
- **数据来源**：企查查 + 新闻 / 公告（SciBERT 事件抽取）。
- **获取可行性**：中。
- **优先级**：P1（直接喂给时空图谱的时间切片）。

### 4.6 投资机构知名度  `investor_prestige` ｜ P1
- **定义**：参与投资机构的头部程度，信用背书信号。
- **口径**：投资机构等级打分（头部 VC / 产业资本 / 政府引导基金 / 个人天使），取企业投资方最高等级或加权。
- **数据来源**：企查查（投资机构工商画像）。
- **获取可行性**：中。
- **优先级**：P1。

## 5. 融合特征类（2 项）

### 5.1 技术转化效率  `tech_conversion` ｜ P1
- **定义**：技术产出转化为商业 / 成长成果的效率，是"技术要素→成长轨迹"的桥梁。
- **口径（草案）**：`营收 CAGR / 专利 CAGR`（产出增长弹性），或 `授权专利数 / 研发人员数`（人均技术产出）。
- **数据来源**：CNIPA + 财报 / 企查查。
- **获取可行性**：中（依赖两类基数均可得）。
- **优先级**：P1（本项目双维融合的核心创新指标）。

### 5.2 资本技术协同度  `cap_tech_synergy` ｜ P2
- **定义**：资本注入后技术产出的边际提升，刻画"钱是否用在刀刃上"。
- **口径（草案）**：融资后 N 个季度内 `专利产出增速` 相对融资前的提升幅度（差分）。
- **数据来源**：企查查（融资时点）+ CNIPA（专利时序）。
- **获取可行性**：低（需精细时序对齐）→ **P2，先不做，模型稳定后再补**。
- **优先级**：P2。

## 7. 优先级与排期建议

- **P0（必取，模型核心，9 个字段）**：inv_patent_ratio、grant_rate、rd_intensity、rev_cagr、funding_to_last_val + 融合待定。→ 决定模型下限，先 mock 跑通 T14。
- **P1（重要，争取）**：其余技术要素 / 成长轨迹指标 + tech_conversion。
- **P2（视可得性）**：cap_tech_synergy，模型稳定后补。

**建议执行顺序**：T10（数据源清单）→ 先 mock 全部 P0 跑通 T14 → 再接真实源补齐 P1 → 最后评估 P2。

## 8. 待确认 / 风险

1. **数据授权与经费**（Q1 / Q3）：外部源接入前提，本周内须找指导教师确认。
2. **rd_intensity 与 rev_cagr 可得性差**：默认采用替代口径（研发人员占比 / 估算），校验组（T13）需做敏感性说明，避免口径偏差污染模型。
3. **专利被引稀疏**：中小科技企业被引少，需设计零值 / 对数变换策略（T11）。
4. **融合特征口径未定型**：5.1 / 5.2 为草案，待模型组（施汶邑）反馈后再冻结。
5. **时间对齐**：融资时点与专利时序的季度对齐是 cap_tech_synergy 的难点，留到 P2 阶段。
