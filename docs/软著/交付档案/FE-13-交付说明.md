## 二、四区块交付明细

### A1 模型架构与训练曲线（`train-curve`，A08 + A09）

**架构图**是手写 SVG，不用图片：五节点横向排列，`input → {gat, temporal} → fusion → head`，六条边标注"节点特征 + 邻接 / 季度序列 / z_s / z_t / z"。
SVG 的好处是文字可选中、可被读屏、缩放不糊，且**改契约字段就能改图**（节点 `label` / `detail` 全部来自 `architecture.nodes`）。

**训练曲线**一张图两个 y 轴，是本页唯一允许双轴的地方：

- 左轴 loss **0.2–0.8**（训练 + 验证两条实线）；右轴 AUC **0.44–0.72**（虚线）。
- 两条 y 轴量程都卡死，不自动缩放——自动缩放会把 0.02 的波动画成剧烈震荡，读起来像"训练不稳定"。
- 噪声地板 0.477 一条红色虚线横在右轴量程下部：**曲线起点就贴在这条线上**（首轮 AUC 0.486–0.490），说明没学之前模型等于随机。
- 最优轮：橙色 `markLine`（竖线）+ `markPoint`（钉在曲线上的标注），该点数值 = 实测 holdout AUC。
- 早停轮：灰色虚线，注明"回滚到最优轮"。

四组曲线（契约值，`epochs` 为实际轮数）：

| 模型 | 轮数 | 最佳轮 | 最佳验证 AUC | 早停轮 | 最终 AUC | 首轮 AUC |
| --- | --- | --- | --- | --- | --- | --- |
| HeteroGAT（图模型） | 120 | 113 | **0.5721** | 120（未触发） | 0.5643 | 0.486 |
| 无图 MLP（对照） | 120 | 81 | 0.5592 | **97（触发）** | 0.5465 | 0.488 |
| XGBoost | 100 | 92 | 0.5763 | 100（未触发） | 0.5595 | 0.4884 |
| Logistic 回归 | 80 | 48 | 0.5862 | **60（触发）** | 0.5821 | 0.4901 |

> **早停不是随便画的**。第一版按"跑满轮次 + 随手截断"生成，结果 gat 在第 20 轮就"早停"、xgb 反而不停，与真实训练语义相反。
> 现在按真实语义生成：`monitor = val_loss`、`min_delta = 1e-4`、`patience = 14`，触发即回滚到最优轮。
> 这让"LR 只跑 60 轮就停、GAT 跑满 120 轮"这个结果有了可解释的原因——**线性模型收敛快、也更快见过拟合**。
> `best_val_auc` 锚死 benchmark 的实测 holdout AUC（`api-smoke` 有断言 `|Δ| < 5e-5`），曲线不是凭空的数。

曲线下方三条事实与一段**重建口径**说明（`derived: true` + `derivation`），措辞统一为"锚点重建"，不出现"实测训练日志"。

### A2 基线对比与消融（`benchmark` 无损扩展，A10）

保留 FE-11 已有的「结论先行 / 4 张 KPI / 行级 vs 企业级 / T1 明细 / T2 CV / T3 特征」，新增三块：

1. **分组柱**：5 项指标（AUC / KS / 准确率 / 召回率 / F1）× 4 个模型，同指标并排。
   - 上方四个 chip 即筛选器（`aria-pressed`），**全部取消时自动回退全选并给出提示**——否则用户看到空坐标轴且无从恢复。
   - 未选中的模型 `selected` 不参与渲染，不是"画成灰色"：灰色会被误读为"数值很低"。
2. **六轴雷达**：只看"同一模型是否偏科"，**不比面积**。
   - 六根轴量程各不相同（精确率 0.10–0.16 vs 召回率 0.30–0.75）。统一量程会把精确率压成贴圆心的一条直线，什么也看不出来。
   - ⚠️ **踩坑记录（值得写进规范）**：ECharts 5 的雷达对每个 indicator **无条件**调用 `alignScaleTicks`（`node_modules/echarts/lib/coord/radar/Radar.js` 里直接调，没有 `alignTicks` 开关）。只要 indicator 写了 `min/max`——哪怕写 `0–1`——刻度凑不出整齐值就刷 `The ticks may be not readable...`，把"无控制台告警"的验收项整条弄红。
     实测 `splitNumber` 取 4 时会刷、取 5 时不刷，纯属刻度对齐的巧合。
     最终方案：**数据侧按各自量程归一化到 0–1，轴侧不写 min/max，真实量程写进轴名**（`AUC` 换行 `0.45–0.62`）+ 提示框换回原始值（`toFixed(4)`）。
     副作用是正向的：量程从"藏在配置里"变成"直接印在图上"，读者不会再误以为 AUC 那根轴的起点是 0。
3. **消融横向柱**：6 条，`full` 为实测基准（Δ = 0），其余 5 条按 Δ 构造并标 `derived`。

   | 去掉的组件 | Δ AUC | 说明 |
   | --- | --- | --- |
   | 完整模型 | 0.0000 | 实测，基准柱 |
   | 去图结构 | **−0.0138** | 反事实（虚线描边） |
   | 去时间分支 | **−0.0215** | 影响最大的一项 |
   | 去时空融合 | −0.0050 | 反事实 |
   | 去注意力 | −0.0029 | 反事实，影响最小 |
   | 去时间边 | −0.0104 | 反事实 |

   **只有"完整模型"是实测值**，图注直接写"本图有 5/6 条为按 Δ 构造（derived）"，柱子上虚线描边区分反事实。
4. **2×2 对照矩阵**：有图/无图 × 含技术要素/仅面板字段。两格 `blocked`（`P0-4` 专利数据未接入），用斜纹底 + "缺数据"标注，**不填 0、不填占位值**。图注讲清"图结构增益只能在无技术要素条件下测，这可能是 +0.013 偏小的原因"。

### A3 ROC / PR / KS 曲线族（`roc-pr-ks`，A11）

模型 tab 单选（4 条曲线叠一张会糊成一团，且 ROC 区间只有 0.55–0.60），三张图各管一件事：

- **ROC**：`x` 用 **log 刻度（0.1%–100%）** —— 这是本页最值得说的一个技术决定，见下方踩坑。
  KS 点用红色 `markPoint` 直接标在曲线上，标注值为**实测 KS**。
- **PR**：带**随机基线**（precision = 正例占比 10.74%，红色虚线）。
  没有这条线，读者会把 precision 0.13 当成"很差"；有了它才知道真实含义是"只比掷骰子高一点"。
- **KS**：TPR（正例累计）/ FPR（负例累计）双曲线 + 间隔 `markArea` 黄金带 + KS `markPoint`，x 轴为分数阈值（反向排列，从 1.00 扫到 0.00）。
- 图下**合成 KS 与实测 KS 并列对账**：`合成曲线 KS = 0.1224，实测 KS = 0.1692（差 +0.0468）`，并写明"曲线族只用于看形状，结论一律以实测 KS 为准"。

> **ROC 为什么必须用 log 轴**：AUC≈0.58 的模型，TPR 要到 FPR≈0.05 才明显爬起来，而 0–0.05 只占线性轴的 5%。
> 第一版用线性轴 + 二分法求点，画出来是"贴着左边墙、贴着上边墙"的直角折线，看起来像图跑坏了。
> 三个原因叠加：①二分方向写反（`1 - Phi(mid) > f`），②FPR 只保留 3 位小数，0.001 到 0.01 之间全被四舍五入成同一个值，③线性轴。
> 修法：阈值从高到低直接扫（不二分）、FPR 保留 6 位、x 轴改 `type: 'log', logBase: 10, min: 0.001`。现在左上角那一段（真正体现区分度的部分）被拉开，且与 AUC 数值自洽。

### A4 置换对照与噪声地板（`noise-floor`，A12）

全项目最重要的一张图：把「观察到的 AUC」和「打乱标签后还能拿到的 AUC」放在**同一把尺子**上。

| 分组 | 柱 | AUC ± std |
| --- | --- | --- |
| 观察组 | 行级 Logistic | 0.5958 ± 0.040 |
| 观察组 | 行级 XGBoost | 0.5952 ± 0.025 |
| 观察组 | 留出集 HeteroGAT | 0.5721 |
| 观察组 | 企业级 Logistic | 0.4735 ± 0.031 |
| 观察组 | 企业级 XGBoost | 0.4788 ± 0.043 |
| 对照组 | 打乱标签 LR | 0.4920 ± 0.056 |
| 对照组 | 打乱标签 XGB | 0.4769 ± 0.040 |
| 对照组 | 随机打分（均匀） | 0.5040 ± 0.030 |
| 对照组 | 打乱特征列 | 0.5150 ± 0.030 |

- 观察组/对照组**两种底色分区**，中间一条 0.477 红色虚线（噪声地板）+ 一条 0.5 灰色虚线（抛硬币）。
- 每根柱带 `±std` 标签（有 std 才画）：单次结果比大小是这类图的常见误读。
- 差额表把减法替读者做完：`行级 LR +0.1188（+24.9%）` / `行级 XGB +0.1182（+24.8%）` / `留出集 GAT +0.0951（+19.9%）`。
- 结论条直接给判断：「行级最好成绩 0.5958，比地板高 +0.119；企业级 0.4735 / 0.4788 与地板持平甚至更低。→ 现阶段模型没有可外推的区分力，瓶颈在数据不在算法。」
- **「地板不是及格线」**：它是"标签被打乱后模型还能捞到多少"的**期望值**，真信号的标准是"显著高于地板"，不是"高于 0.5"。
- 五种对照口径列成表（打乱标签 / 企业级打乱 / 随机打分 / 打乱特征列 / 置换重要性），后三种标「合成」。

## 三、接口与契约

| 端点 | 契约文件 | 体积 | 关键内容 |
| --- | --- | --- | --- |
| `GET /api/model/train-curve` | `train_curve.json` | 41.8 KB | `architecture`(5 节点/6 边) + `curves`(4 条 × 120 轮 × 5 序列) + `synthetic_anchor` |
| `GET /api/model/benchmark` | `benchmark.json` | 15.9 KB | 原 `levels`/`holdout` 不动，+ `grouped`/`radar`/`ablation`/`matrix`/`conclusion` |
| `GET /api/model/roc-pr-ks` | `roc_pr_ks.json` | 51.7 KB | 4 条曲线族（ROC 99 点 / PR 101 点 / KS 21 点）+ `ks.measured` |
| `GET /api/model/noise-floor` | `noise_floor.json` | 5.5 KB | 9 根柱 + 5 种对照策略 + 3 行差额 + verdict |

**契约由脚本生成，不手写**：`python3 scripts/build_model_contracts.py`（零外部依赖，自带 LCG，`seed = 20261026` 可完全复现）。
`npm run contracts:model` 已挂到 package 脚本。

### 3.1 实测数值零污染：`benchmark.json` 是"读改写"不是"重生成"

这是本次交付最要紧的一条纪律。`benchmark.json` 里的每一个 AUC / KS 都是项目已跑出的实测结果，**任何重生成都有把实测数换成"好看的数"的风险**。所以脚本这样写：

```python
def load_anchors():
    """优先从已有 benchmark.json 读实测锚点，原样写回；只有文件缺失才用内置冻结表"""
    ...

# 扩展时只追加新键，不动 old["data"]["levels"] / old["data"]["holdout"]
```

`--keep-frozen` 参数只在内置冻结表需要更新时才用。验收时直接 `diff` 新旧文件的 `data.levels`，结果 **逐字节相同**（`api-smoke` 另有 22 项断言守着这些锚点）。

### 3.2 新增内容的 `derived` 纪律

凡是"由实测端点约束生成"的内容，一律三件套齐全：

```json
{
  "derived": true,
  "derivation": "AUC 端点锚定：第 1 轮 ≈ 噪声地板 0.477，早停回滚后的最优轮 = 实测 holdout AUC 0.5721；形状用 1-exp(-epoch/52) 饱和。训练 loss 为合成曲线，不代表真实训练日志。",
  "meta.source": "reconstructed_from_anchors"
}
```

`meta.source` 不是 `measured` 的区块，角标语气自动升为 warning、文案写「锚点重建」而不是「实测结果」——**这件事由组件从 meta 推导，页面无法override**。

## 四、红线落地

| 红线 | P4 的落地方式 | 验收方式 |
| --- | --- | --- |
| ① 同一图表不得混排数据来源 | `ChartPanel.dataset` 是必填 prop；四区块各自 `SectionBadge` 读各自 `meta`，组件内无缓存、无跨区块复用 | 冒烟断言四颗角标的 `data-dataset`/`data-source` **逐一等于**对应契约的 meta |
| ② 语义未知字段只显 `xNNN` | 特征列表统一走 `UnknownFieldTag`；A1 架构图里 no 字段名 | 冒烟断言全页 `xNNN` 出现 43 处、无伪造业务字段名 |
| ③ 真实面板性能图同屏噪声地板 | A2 / A3-ROC / A4 三处都带 0.477 注记；A1（合成图）与 A3 的 PR / KS（指标不是 AUC）**不显示** | 见下方「修掉的半句话」 |
| ④ 不同数据集不同图 | 0.9149 只在 A1 出现，同屏「不进本页任何真实面板坐标轴」；A1 角标常驻「合成图，不与真实面板对比」 | 冒烟断言 A1 含 0.9149 + A2/A3/A4 正文各 0 处 |

> **修掉的一个真实缺陷**：`ChartPanel` 原来判断"要不要显示噪声地板注记"写的是 `noiseFloor !== undefined`。
> 于是显式传 `null`（不适用）的图也会渲染注记，屏幕上出现 **「噪声地板 AUC = —，低于此值即与随机无异」** 这种半句话——A3 的 PR 与 KS 图上各出现一次。
> 改成 `typeof noiseFloor === 'number' && Number.isFinite(...)` 后消失：PR / KS 图不再挂一条讲 AUC 的提示，ROC 图仍保留（它是 AUC 的图）。
> 这类"参数传了就该生效"的默认值陷阱，靠逐张截图目检才抓得到，冒烟断言本身抓不到。

## 五、取数纪律与降级

四个区块**各自独立**走 `useAsyncSection`（A1 挂了不会把 A2 拖成空白）。契约未就绪时按 `LABEL_PENDING` 式降级：

- 每块独立 `StatePanel variant="pending"`，标题写清是哪一块、`reason` 写缺哪个字段、`nextStep` 直接给命令 `python3 scripts/build_model_contracts.py`。
- 页面顶部 `failedSections` 清单会把**所有**取数失败的区块列出来（"A3 ROC/PR/KS 曲线族 —— 请求超时"这种），避免用户只看到局部空块不知道全貌。
- 300ms 骨架阈值 + `requestId` 竞态守卫（旧响应晚到直接丢弃）。

> **本次修掉的两个真实 bug（都表现为"区块全部停在未就绪"）**：
> ① `useAsyncSection` 的 `data` / `error` 用了 `shallowRef`，页面读 `section.data.value.data` 永远是 `undefined` —— 改成 `ref`。
> ② 页面 `pick()` 把 composable 返回对象整个传进去，`env?.data` 取到的是组件代理而不是 ref 值 —— 改成显式 `pick<T>({ data: curveSection.data.value })`。
> 两个 bug 都只在**真浏览器**里暴露（`vue-tsc` 不报错，`renderToString` 只拿到骨架），这也是为什么 P4 必须有 Playwright 冒烟。

## 九、已知限制与后续

1. **A1 的曲线是锚点重建，不是真实训练日志**。起点钉在噪声地板、最优轮钉在实测 holdout AUC、形状用饱和函数拟合，`derived` / `derivation` / `source` 三处都已声明。
   要换成真实日志，只需让 `build_model_contracts.py` 读训练脚本落盘的 `history.json` 覆盖 `curves`，**前端零改动**。
2. **A3 的逐样本得分是合成的**。ROC / PR 由"AUC 约束的双高斯"生成，KS 曲线取解析最大值，所以合成 KS（0.1224）与实测 KS（0.1692）差 0.047。
   页面上两个数并列展示并写明"结论以实测为准"——**不做隐藏、也不调参让两个数对上看**（那才是造假）。真实逐样本得分落盘后即可替换。
3. **A10 消融里只有「完整模型」是实测**。其余 5 条按 Δ 构造，柱子上虚线描边 + 图注写"5/6 条为 derived"。要跑真消融需重训 5 次（合成图 CPU 每次 < 2 分钟，可行但属于算法组排期）。
4. **2×2 矩阵有两格缺数据**（`P0-4` 专利数据未接入）。两格用斜纹底 + "缺数据"，不填占位值。补齐后"图结构增益 +0.013 是否偏小"才有答案。
5. **企业级 AUC 0.47 低于抛硬币**不是 bug，是结论。页面用 4 张 KPI + 行级/企业级对比图把这件事摆在最显眼的位置，不试图"修好看"。
6. **P6 前瞻预测、P7 单企业深度诊断仍是占位页**，等 FE-14 / FE-15。
