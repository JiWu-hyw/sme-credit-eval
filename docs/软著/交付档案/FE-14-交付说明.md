## 二、两区块交付明细

### A13 全局特征贡献排序（`explain/global`，A13，真实契约）

**三块内容共用一份契约、一次取数、一个排序状态**，这是刻意的：条形图、蜂群图、明细表必须说同一件事，谁也不许自己排一遍。

#### 1）条形图（`#a13-bar`）

- 横向柱按 `mean_abs_shap` 降序，Top-20 全画（不分页、不加"查看更多"）。
- 柱子颜色区分方向：风险因子（`direction: +1`，值越大越推高违约概率）与保护因子（`direction: -1`）**用形状也区分**，不只靠颜色——色盲用户看图例外的柱端标记也能分辨。
- 标签直接标数值（4 位小数），不让人去轴上看刻度。
- **`:noise-floor="null"`**：SHAP 的量纲是"对 log-odds 的平均绝对贡献"，跟 AUC 地板 0.477 不是一个东西。这条是本次修掉的真实缺陷（见 §四）。

#### 2）蜂群图（`#a13-beeswarm`）

这是本轮花时间最多的一张图，难在三件事：

**① x 轴要全行共用。** 每行一个特征、每行 200 个点，如果每行各自按自己量程铺满，`x125` 的 ±0.10 和 `x58` 的 ±0.01 会被画成一样宽，读起来"贡献差不多"——正好是反的。所以 `swarmRange()` 先扫全部行求全局范围，再对称取 `±max(|lo|,|hi|)` 并**向上取整到 0.05 的倍数**（XGBoost 得 `±0.35`，Logistic 因为 SHAP 量纲是原始 log-odds，得 `±2.70`）。取整是为了坐标轴刻度好读，也让轴范围可预期；**两个模型轴范围不同是正常的**——LR 的 SHAP 本来就在线性尺度上，跟树模型的取值不能直接比大小，所以模型切换时轴跟着换，不硬拉成同一把尺子。

**② 点位要确定性避让，不能用随机抖动。** 蜂群图传统做法是随机 jitter，但同一份数据刷两次长得不一样，截图不可复现、也没法断言。改成按 x 分箱（34 箱）+ 箱内对称偏移（最大 0.34 行高）：

```ts
// frontend/src/utils/beeswarm.ts
export function layoutSwarm(points, row, range, { bins = 34, maxOffset = 0.34 } = {}) {
  // 同一箱内第 k 个点 → 偏移量按 0, +d, -d, +2d, -2d… 交替展开
  // 保证：确定性、不丢点、不越行、孤点不偏移
}
```

`layoutSwarm` 被抽成纯函数单独放在 `utils/` 下，好处是冒烟测试能直接 `ssrLoadModule` 把它拉进来跑 5 项纯函数断言（不用起浏览器）。

**③ 点位是重建的，必须当场说清楚。** 图下方一条常驻注记：

> 点位口径：逐样本 SHAP 值未随契约落盘，本图按实测 `mean|SHAP|` 与实测方向重建 200 个样本点（`reconstructed_from_anchors`）——均值与方向是实测的，分布形状是重建的。要换成真实点位，只需算法侧把 `shap_values.npz` 落盘后由脚本覆盖 `points`，前端零改动。

颜色映射特征值 z-score：`#2f5d8a`（低）→ `#cfd6dd`（均值 0）→ `#b3312c`（高）。**z-score 的符号必须跟 `direction` 一起翻转**——否则保护因子（`direction: -1`）会画成"值越大越推高违约"，跟条形图讲的正好相反。这个坑实际踩过：第一版没翻，`x125` 的秩相关符号直接反了（`ρ=0.607`，被脚本的 self-check 拦下）。

**采样口径同屏可见**：`每行200点/解释集698`，读的人在图表内部就能看到抽样比例，不用去翻契约。

#### 3）Top-20 明细表（`#a13-toplist`）

- **20 行全部展开**，不设 `max-height` 滚动。理由跟 P4 一样：Top-20 是本页的核心证据，截图归档时"只露 18 行"会被当成数据缺失。
- 列：`#` / 字段 / `mean|SHAP|` / 占比 / 方向。`#` 列**恒为契约里的 `rank`**——排序只改观看顺序，不改编号。这一条有专门断言守着。
- 字段列一律 `UnknownFieldTag`（`x125` 这种），不出现任何业务名。

#### 4）三种排序

| 排序 | 逻辑 | 用途 |
| --- | --- | --- |
| 实测贡献（默认） | 按 `rank` | 标准视角 |
| 风险因子优先 | `direction: +1` 在前，组内仍按实测 rank | 「哪些字段会推高违约」 |
| 按字段代号 | 按 `xNNN` 数字升序 | 想找某个特定字段时 |

排序是前端纯状态，**不重新请求、不改契约**。切排序时条形图和蜂群图一起换序（同一个 `rows` computed），保证两张图永远说同一件事。

### A15 阶段-因子-权重动态决策图谱（`explain/stage-factor`，A15，mock）

A15 的真实契约被两个上游阻塞（`meta.blocked_by: ["P0-2", "P0-5"]`）：字段字典未补齐 → 维度归属无法推导；融资事件未到位 → 阶段划分没有真实轮次锚点。所以这一块是**结构同构占位**。

**页面怎么处理"占位"**——这是 A15 唯一值得细说的地方：

1. 区块顶部一条 warning 语气的警示条（`data-testid="stage-mock-strip"`），文案直接说三件事：契约未就绪、阻塞项是谁、**哪部分是实测的**。原文：

> 本区块的阶段划分与权重属占位值，字段排序与 mean|SHAP| 是实测值。
> A15 真实契约未产出（P0-2 字段字典未补齐、P0-5 融资事件未到位）。本文件为结构同构占位：阶段划分、维度权重、阶段内字段权重均为占位值；字段排序与 mean|SHAP| 取自实测 `shap_global.json`，不得作为实证结论引用。
> 解锁条件：x21–x200 字段字典（维度归属才能由字典推导，而不是由原型图拼）；融资事件表（阶段划分需要真实的轮次与时间点，不能只靠成立年限）。字段字典到位后，`weights` 由字典推导的分组重算，`stage_fields` 换成真实分组归因；前端零改动。

2. **角标自动升 warning**：`meta.source` 不是 `measured` 的区块，`SectionBadge` 的语气从"实测结果"切到「真实信贷面板 · 占位数据」。这件事由组件从 meta 推导，**页面无法 override**。

3. **`decision_notes` 的写法反复改过一版**。第一版写"首位占 100%"，原因是阶段内字段权重归一化后首位就是大头——读起来像 bug。改成现在这样，把"占位"和"实测"两个数放在一句话里各就各位：

> 权重集中在「成长轨迹」（占位 42%）。字段层面首位 `x125` 占该阶段 29.4%（占位），前 3 位合计 60.5%；其 `mean|SHAP|` 0.0801 为实测。字段语义未确认，此处只做算法层陈述，不指向任何业务含义。

**图表形态**（`#a15-chart`）：

- **100% 堆叠面积**，每个阶段一列，3 个维度自底向上：技术要素 `#2f5d8a` / 成长轨迹 `#c08a1e` / 融合特征 `#7a5fa8`。
- **不 smooth**（`smooth: false`）。只有 4 个离散阶段，画成平滑曲线就是在暗示"权重在阶段之间连续漂移"——而契约里根本没有阶段之间的数据。这条写进了图注：

> 怎么看：每一列高度恒为 100%，比较的是结构而不是总量；虚线是当前选中阶段。阶段间用直线连接——4 个离散区间之间没有"连续漂移"的证据，画成平滑曲线就是过度解读。

- `boundaryGap: true`，让 4 个阶段各自居中成一列，而不是首尾贴边。
- 点击图上任意阶段或上方 chip 都能切换，`data-stage_id` 透传。

**右侧权重卡 + 下方字段明细**：

| 区域 | 内容 |
| --- | --- |
| 阶段 chips | 4 个按钮，每个带阶段名 / 年限 / 融资标记 / 企业占比 |
| 因子权重卡（`#a15-weights`） | 3 条进度条 + 百分比，每张卡下方写明"维度归属为占位"，阶段内合计 100.0% |
| 字段明细（`#a15-fields`） | 8 行，`mean|SHAP|` 与方向为实测，`stage_weight` 标注「占位」并带相对条 |
| 结论条（`stage-note`） | 对应当前阶段的 `decision_notes`，末句固定「不指向任何业务含义」 |

**字段来源是实测的**：`stage_fields` 取 `shap_global.json` 里 XGB 的 `top[:8]`（`x125 / x193 / x60 / x22 / x59 / x165 / x144 / x108`），`mean_abs_shap` 与 `direction` 原样带来。所以"切阶段时字段表换组"这件事本身是可信的——换的是**权重**，不是**排序依据**。

## 三、接口与契约

| 端点 | 契约文件 | 体积 | 关键内容 | 状态 |

| `GET /api/explain/stage-factor` | `stage_factor_weight.json` | 14.0 KB | `stages`(4) + `factors`(3 维度) + `weights`(12) + `stage_fields`(4×8) + `decision_notes`(4) + `unlock` | **mock** |

`npm run contracts:explain` 已挂到 package 脚本。

### 3.1 实测数值零污染：`shap_global.json` 同样是"读改写"

`mean|SHAP|` 与 `direction` 是项目已跑出的实测结果。脚本的纪律跟 FE-13 的 `benchmark.json` 一样——**只追加键，不动旧值**，而且这次把 self-check 写死在脚本里：

```python
# 快照原 top / top20_share / conclusion，写回后逐字段比对
before = {m["model_id"]: (deepcopy(m["top"]), m["top20_share"]) for m in old["data"]["models"]}
before_conclusion = old["data"]["conclusion"]
...
if after != before or new["data"]["conclusion"] != before_conclusion:
    raise SystemExit("[shap_global] 实测字段被改动，拒绝写盘")
```

任何一次误改都会让脚本直接退出、不写文件。验收时 `api-smoke` 另有 8 项断言守着这些锚点（含 `top20_share` 精确到 5 位小数）。

### 3.2 蜂群点位的重建算法

不是随手撒点，是**双重锚定**：均值精确对齐、方向符号一致。

```python
# 幅度：对数正态 → 乘性放大 → 截尾（BEESWARM_CAP=4.0）→ 再归一
mags = [math.exp(SIGMA * row_rng.normal() - SIGMA**2 / 2) for _ in ids]
mags = [min(m / scale, CAP) for m in mags]          # 截尾
mags = [m / scale2 * mu for m in mags]              # 再归一 → mean|SHAP| 精确等于实测

# 符号：主方向占 74%，反向占 26%（BEESWARM_FLIP）
# 特征值 z：0.60 * direction * a + 0.80 * b   ← direction 必须参与，否则保护因子画反
```

截尾后再归一这一步不能省：只截尾不归一，`mean|SHAP|` 会系统性偏低，散点均值就与条形图的数字对不上（而那个数字是实测的）。

自校验结果写进契约，可被断言：

```json
"beeswarm_meta": {
  "derived": true,
  "source": "reconstructed_from_anchors",
  "derivation": "逐样本 SHAP 值未随契约落盘：本区块以实测 mean|SHAP|（逐特征精确对齐，Δ<1e-9）与实测方向（秩相关符号一致）为锚点，按「对数正态幅度 × 主方向符号（26% 反向）」重建 200 个样本点。点位形状是重建的，均值与方向是实测的。",
  "max_mean_deviation": 2.5e-07
}
```

`max_mean_deviation` **记的是"读契约的人能验到的那个值"**：按落盘的 5 位小数为点位重算均值，XGB 最大偏差 `2.5e-07`、LR `4e-07`（算法内部对齐精度是 1e-9 级，但点位为控制体积做了 5 位小数舍入）。这个字段进了 `api-smoke`，而且有一条专门的断言核「契约里写的数 == 按点位复算的数」——**契约说自己偏差 0、读者一算得到 4e-7，那种不一致本身就是一种失真**，所以宁可写小偏差也不写漂亮的 0。

### 3.3 体积控制：490 KB → 116.6 KB

200 点 × 15 特征 × 2 模型 = 6000 个 `[x, y]`。indent=2 展开成 6 行一个点，文件 490 KB、完全没法 `diff`。加了 `dump_json()`：**只把 `points` 二维数组压成一行**，其余结构保持 `indent=2`。

```python
def dump_json(path, obj):
    """points 压成一行（每特征一行），其余保持缩进 2，保证契约可 diff"""
```

结果 116.6 KB（gzip 33 KB），且 `git diff` 时每个特征只占一行——改了点位能一眼看到是哪个特征、改了多少。

## 四、红线落地

| 红线 | P5 的落地方式 | 验收方式 |

| ③ 真实面板性能图必须同屏噪声地板 | **A13 不挂**（SHAP 不是判别力指标）；0.477 只在 KPI 卡片里出现，用来讲"模型现在能不能用" | 冒烟断言 A13 正文 `不含「噪声地板」`（回归项），同时断言全页仍保留 `0.477` 说明 |
| ④ 不同数据集不同图 | 0.9149 全页 0 处；A13 用的是 `real_panel` 契约，同屏没有任何合成图数字 | 冒烟 + `redline-smoke` 双查 |

> **修掉的一个真实缺陷（跟 P4 是同一个坑，但表现形式不同）**：
> P4 的问题是 `noiseFloor !== undefined` 让显式传 `null` 的图也渲染注记（屏幕上出现「噪声地板 AUC = —」）。
> P5 更直接：`ExplainView` 早期版本给 A13 条形图**传了 0.477**，于是 SHAP 图下方挂了一句「噪声地板 AUC = 0.477，低于此值即与随机无异」——把"某特征贡献 0.08"和"模型判别力 0.477"两个不同量纲的东西并排放在一起，读者只会得出错误结论。
> 现在 A13 显式传 `:noise-floor="null"`，并在冒烟里加了一条**反向断言**（A13 正文不含"噪声地板"），防止有人"为了统一"又给它加回去。

> **另一处自我纠正**：`max_mean_deviation` 第一版写的是舍入前的内部值（`0.0`），但落盘点位保留 5 位小数，读契约的人按点位复算会得到 `4e-07`。
> 契约声称 0、读者算出 4e-7，这种不一致**本身就是一种失真**——虽然 4e-7 完全不影响结论。
> 改成记"读者能验到的那个值"，并加一条断言核「契约里写的 == 按点位复算的」，同时把阈值放到 1e-6（再大就说明舍入真的伤到数了，脚本会 `SystemExit`）。

## 五、取数纪律与降级

两个区块**各自独立**走 `useAsyncSection`，互不牵连：

## 九、已知限制与后续

1. **A13 蜂群图的点位是重建的，不是真实逐样本 SHAP。** 这是本交付最需要读者知道的一条。
   均值（`max_mean_deviation = 0.0`）和方向（秩相关符号逐特征一致）是实测的，**分布形状是重建的**。
   所以这张图能回答"这个特征的贡献有多大、往哪个方向推"，**不能**回答"这个特征在高值区间是不是更分散"这类形状问题。
   解锁方式明确：算法侧把 `shap_values.npz` 落盘 → 脚本读它覆盖 `points` → **前端零改动**。
2. **A15 整块是 mock。** 阶段划分、维度权重、阶段内字段权重全部是占位值。页面已经用「警示条 + warning 角标 + 每张卡下方的"维度归属为占位" + 结论末句"不指向任何业务含义"」四重标注兜住，但**它仍然不能作为实证结论引用**。
   阻塞项是 `P0-2`（字段字典）和 `P0-5`（融资事件），两个都不是前端能推的。
3. **A15 的"维度"是自建三维护口径，不是业务因子。** `tech` / `growth` / `fusion` 三个维度名来自原型图，不是从字段字典推导出来的。任务卡要求"字段字典补齐前只做算法层解释，不写死业务因子名"——所以页面上它们标 `label_kind: "dimension"`，卡片明写"维度名不代表字段真实含义"，**不写"专利因子""融资因子"这类会被当成业务结论的名字**。
4. **`top20_share` 两模型差异很大（XGB 92.1% / LR 80.1%）**，这是真实的：线性模型把权重摊得更均匀。页面上并列展示，不做归一化掩盖。
5. **A13 结论「当前模型有效但不可解释」是个不太好看但必须说的结论**：Top-20 里语义已知字段 **0 个**，`|SHAP|` 几乎全部落在 x21–x200。这句话原样来自契约（`conclusion` 字段，本轮未改），页面上放在最显眼的位置——把"瓶颈在字段字典"这件事摆出来，比画一张漂亮的图有用。
6. **P6 前瞻预测、P7 单企业深度诊断仍是占位页**，等 FE-15 / FE-16。
