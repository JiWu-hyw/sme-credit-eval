## 二、四区块交付明细

### E1 六类实体异质图（`/api/graph/structure`，A05）

力导向异质图，六类实体按类型着色、节点大小按度数、边按关系类型分色。

| 类型 | 数量 | 颜色语义 |
| --- | --- | --- |
| 企业 company | 180 | 深蓝（主体） |
| 专利 patent | 630 | 紫（叶节点，度集中在 2） |
| 投资机构 investor | 16 | 琥珀 |
| 核心人员 person | 40 | 绿 |
| 技术领域 field | 6 | 棕（枢纽，度 97–118） |
| 产品 product | 6 | 玫红 |

- **图例即筛选器**：6 个按钮带 `aria-pressed`，点一下即该类显隐；全部关掉自动回退全选（否则用户会看到一片空白且无从恢复）。
- **选中高亮 1 跳邻居**：点节点后其余节点降到 15% 不透明度，只留它的邻居——异质图上"它连了谁"是最常问的问题。
- **三重过滤**：类型 → 季度可见集 → 无悬空边。任一节点被滤掉时，挂在它上面的边同步消失，不会画出一根指向虚空的线。
- **抽样口径写在图上**：`当前绘出 150 个节点 / 268 条边（全图 878 节点，按「度优先 + 每类保底」抽样）· 时间窗口：全时段`。

> 抽样策略踩了三轮才定：① 纯按度优先 → 抽进来全是个位数度的专利，领域/产品枢纽一个没进；
> ② 度优先预填种子 + BFS → 预填阶段就耗尽 150 额度，BFS 一步没走；
> ③ 终解 = **分类配额**（领域/产品/机构全收，专利 28%、人员 12%，其余给企业）+ BFS 补邻，
> 企业按「已选邻居数」降序填充以接上孤立枢纽。结果 148/150 连通，图上不再是碎岛。

### E2 季度时间切片（`/api/graph/slices`，A07）

回答"图是怎么长出来的"。

| 季度 | 累计节点 | 当季新增节点 | 当季新增边 | 累计边 |
| --- | --- | --- | --- | --- |
| 2024Q1 | 88 | 88 | 120 | 120 |
| 2024Q2 | 206 | 128 | 204 | 324 |
| 2024Q3 | 321 | 125 | 234 | 558 |
| 2024Q4 | 456 | 145 | 294 | 852 |
| 2025Q1 | 578 | 132 | 264 | 1,116 |
| 2025Q2 | 878 | 310 | 648 | 1,764 |

- **单 y 轴**，不是双轴：累计面积叠加 + 当季新增柱 + 当前季度 `markLine`。
  第一版做了双轴（左"新增"、右"累计"），量级相近、读者根本分不清哪根柱子读哪根轴，改成单轴才读得通。
- 滑块可拖、6 个刻度可点、播放按钮 900ms 步进（`aria-pressed` 反映播放态）。
- 切季度会**联动 E1**：E1 显示"截至该季度"的累计子图，节点数从 150 降到 60（契约可见 206 ∩ 抽样 150）。
- 可见集**只认切片契约的 `visible_node_ids`**，不在前端按 `entered_at` 自算——自算会与契约口径不一致，实测差 12 个节点。

### E3 中心性分析（`/api/graph/centrality`，A06）

四张图，逐层回答"谁重要"。

1. **度分布（按度值分档，9 档）**：最大 118 / 均值 4.02 / 中位 2；双峰长尾形态清楚——630 个专利在度 2，174 个企业在 5–8，6 个技术领域在 ≥65。
   - 分档方式迭代两版：等高分箱 → 870 个全挤第一箱；线性等距 → 872 个全挤第一箱。只有**按度值分档（近似 log 刻度）**才能同时看清大头和尾巴。
   - **度 0 的孤立节点单列一档（灰色，10 个）**。不加这档，分档合计 868 ≠ 全量 878，读者一加就发现"图上节点比柱子加起来还多"，而这 10 个恰是抽样跳过的企业——"没连边的机构在图上等于隐身"本身就是要看见的事实。
2. **四类中心性 Spearman 热力图（4×4）**：

   |  | 度 | 介数 | 接近 | 特征向量 |
   | --- | --- | --- | --- | --- |
   | **度** | 1.00 | 0.60 | 0.26 | **−0.30** |
   | **介数** | 0.60 | 1.00 | 0.49 | **−0.31** |
   | **接近** | 0.26 | 0.49 | 1.00 | 0.20 |
   | **特征向量** | **−0.30** | **−0.31** | 0.20 | 1.00 |

   **最弱一对是接近 × 特征向量（ρ = 0.20）**，且度 × 特征向量、介数 × 特征向量为**负相关**。
   页面明确写："这不是算错——二分图里「邻居多」和「邻居重要」是两回事。"
3. **分类 Top 榜**：6 类实体可切换，每类可切四类指标（榜单按当前主指标排序）。默认展示「技术领域」——
   企业节点几乎都是度 8（专利 2–5 + 人员 1–2 + 产品 1 + 投资 0–1），第一版固定按度排，企业榜 15 条全是度 8 的平局，看起来像图坏了。
4. **四维雷达**：Top-6 vs 同类均值，把"这条榜单是不是只在某一个指标上高"一眼看穿。

> **特征向量中心性为什么是负相关**：二分图邻接矩阵的特征值成对出现 ±λ，第一版每步取 `abs()` 让正负模态互相抵消、幂迭代震荡不收敛（秩相关 −0.33，明显是算错的样子）。
> 改用带符号迭代（多数分量为负时整体翻号）后，与 2000 步参考实现对照，秩相关 **1.0**、Top-8 完全一致。
> 修正后仍是负相关 —— 那是**二分图的结构事实**，已在契约 `interpretation` 和页面文案里写明，不是 bug。

### E4 这张图能说明什么、不能说明什么

两栏对照，把"结论边界"写进页面而不是只写进文档：

- **能说明**：六类实体 + 六种语义边 + 按季度增量，图结构可以喂给 GAT；合成图上 STGNN 架构验证 AUC **0.9149**；结构是长尾型，GAT 的注意力要能区分「邻居多」与「邻居重要」；中心性彼此不一致 → 后续局部归因必须声明口径。
- **不能说明**：`dataset = synthetic_graph` 与真实面板行级 AUC 0.59 不是同一数据集，不能同图比较（红线一 + 红线四）；P0-1 / P0-4 / P0-5 未补时专利、融资、人员落不到具体企业；真实面板 2 个月观测深度做不出季度粒度长序列，本页季度切片是**结构演示**，取不取决于这张图跑得多顺。

### 节点详情浮层

点任意节点开右侧抽屉，回答四件事：**这是什么 / 它连了谁 / 它在图上有多重要 / 还剩哪些待补数据**。

- 标题下方常驻合成数据警示——企业名是「合成企业#001」这种占位名，不能当真实企业引用。
- **四维中心性百分位条**：度 74% / 介数 86% / 接近 3% / 特征向量 6%，下方注明"百分位是排名位置，不是绝对值；四类指标口径不同，不能横向比大小"。
- **关联实体按「关系·方向」分组**（授权·出边 / 产出·出边 / 任职·入边 / 投资·入边…），每组最多 12 条。
- `role="dialog"` + `aria-modal="true"` + `aria-labelledby`，Esc 关闭，打开时焦点移入抽屉。

> 这里修了一个真实产品缺口：契约原本只给每类 Top-15，点开一个普通节点（如 `C0071`）浮层里中心性区块**直接不出现**，用户会以为"这个节点没有中心性"。
> 修复 = 契约新增 `node_index` 全量索引（878 个节点的四维百分位，+200KB），抽屉改为三级回退 `overall_top → by_kind_top → node_index`，保证**任何节点点开都有四维数据**。

## 三、接口与契约

三个端点，单一事实源是 `outputs/contracts/graph_*.json`，`src/types/contracts.ts` 是逐字镜像（snake_case 不转驼峰）。

| 端点 | 契约文件 | 体积 | 关键内容 |
| --- | --- | --- | --- |
| `GET /api/graph/structure` | `graph_structure.json` | 84 KB | `nodes`(150 抽样) / `edges`(268) / `entity_kinds` / `edge_kinds` / `stats`(全量口径) |
| `GET /api/graph/slices` | `graph_slices.json` | 52 KB | 6 个季度切片，每片 `visible_node_ids` + 当季新增 |
| `GET /api/graph/centrality` | `graph_centrality.json` | 240 KB | 度分布 9 档 / 4×4 秩相关 / 分类 Top-15 / **`node_index` 全量 878** |

**契约由脚本生成，不手写**：`python3 scripts/build_graph_contracts.py`（零外部依赖，自带 LCG 伪随机，`seed=20261022` 可完全复现）。
抽样参数 `sample_cap=150` 由 `meta` 声明，**页面的"全图 878"读的是 `stats.n_nodes` 而不是 `nodes.length`** —— 这两个数不一样，混用是本页最容易犯的错。

`meta` 里三件必备品：

```json
{
  "dataset": "synthetic_graph",
  "source": "synthetic_graph",
  "noise_floor": null,
  "blocked_by": ["P0-1", "P0-4", "P0-5"],
  "redline": { "no_mixed_dataset": true, "noise_floor_applicable": false, "unknown_fields_shown_as_code": true }
}
```

`noise_floor` 为 `null` 是**故意的**：红线三的 0.477 属真实面板语境，塞进合成图会让读者误以为合成图也要对那条线。
`api-smoke` 专门断言 `redline.noise_floor_applicable === false`，防止后来者"顺手补上"。

## 四、红线落地：机制而不是文案

| 红线 | P3 的落地方式 | 验收方式 |
| --- | --- | --- |
| ① 同一图表不得混排数据来源 | `ChartPanel` 的 `dataset` 是**必填 prop** → 漏传即编译错误；`assertSingleDataset()` 运行期守卫 | 冒烟断言"不出现真实面板 0.596 与合成图同图" |
| ② 语义未知字段只显代号 | 图谱实体名走 `label`，字段代号统一 `xNNN`；`RedLineBanner` 页面级只挂一条 | 冒烟断言全页提示条**恰好 1 条**（曾因选择器写成 `[class*="redline"]` 数出 5 条） |
| ③ 真实面板性能图必须同屏噪声地板 | 合成图**不适用**，`noise_floor = null` + `noise_floor_applicable = false` | `api-smoke` 逐契约断言这三项 |
| ④ 不同数据集不同图 | 合成图 STGNN AUC **0.9149** 只在合成图语境出现，并注明"与真实面板 0.596 不是一个数据集" | 冒烟断言 0.9149 明确标注在合成图语境下 |

E1–E3 全部 6 张图**每张都带「合成图数据 n=878」角标**，冒烟逐个核过（6/6）。
页头常驻一条声明条（`data-testid="synthetic-notice"`），写清 `dataset`、占位名规则、缺口编号 P0-1 / P0-4 / P0-5。

## 五、取数纪律与异常态

三个区块**各自独立**走 `useAsyncSection`：E2 挂了不会把 E1 也拖成空白。

- **300ms 骨架阈值**：本地 mock 秒回时不闪骨架；真慢才出骨架。
- **requestId 竞态守卫**：快速拖滑块/切指标时，晚到的旧响应直接丢弃。
- **`StatePanel` 三件套**：错误态必给 `reason`（为什么）+ `nextStep`（怎么办）+ `retry`（点一下重试），空态必给"去生成契约"的下一步。
- **形状守卫按契约字面写**：E3 第一版把 `by_kind_top` 当数组塞进 `hasArrays`，但契约里它是**对象**，结果 E3 永远空态。改成 `Array.isArray(overall_top) && Array.isArray(metrics) && typeof by_kind_top === 'object'`。
- **全图模式不静默降级**：切到"全图 878"时调 `GET /api/graph/structure?sample_cap=878`；后端不可用时**明确报错**（`data-testid="full-graph-warn"`，文案给出"全图 878 节点"），**绝不回落成抽样版**——否则用户以为自己在看全图，实际看的是 150 的抽样。
- **HTTP 直取**：`httpGetData<T>()` 专门服务这种"细节直取、失败不降级"的场景，与主流程的 auto 降级通道分开。

## 七、复现方式

```bash
cd frontend
npm ci

# 1. 生成图谱契约（零外部依赖，seed 固定可复现）
python3 scripts/build_graph_contracts.py
#   → graph_structure.json 84 KB / graph_slices.json 52 KB / graph_centrality.json 240 KB

# 2. 类型检查 + 生产构建
npm run build          # vue-tsc --noEmit && vite build

# 3. 全量验收（9 条链，347 项）
npm run test

# 4. 单跑 P3
npm run test:p3        # 浏览器冒烟 43 项
npm run shots:p3       # 截图 → docs/preview/p3-*.png

# 5. 本地起生产同构服务
cd .. && PORT=8080 node serve/server.mjs
#   /api/* → 404 + JSON（不回落 index.html）
#   需要真后端时：API_PROXY=http://127.0.0.1:8000 PORT=8080 node serve/server.mjs
```

`VITE_USE_MOCK` 三态：`mock`（全走契约）/ `real`（全走接口）/ `auto`（默认，失败降级 mock）。
`auto` 降级前有 `isEnvelope()` 形状校验，**明确拒绝 `data` 为字符串**——那正是 `/api/*` 回落 HTML 时的症状，不拦的话页面会把 HTML 当数据用。

## 九、已知限制与后续

1. **数据是合成图**。878 节点全部来自 `synthetic_graph`，企业名是「合成企业#001」这类占位名。
   接入真实数据的前置缺口：**P0-1**（userid ↔ 企业映射键）、**P0-4**（专利数据）、**P0-5**（融资事件）。
   三件补齐后，只需重跑 `build_graph_contracts.py` 换数据源，前端零改动。
2. **抽样上限 150 待算法组确认**。当前 150 是"能在浏览器里拖得动"的经验值（ECharts 力导向在 300+ 节点开始明显卡顿）。
   契约已用 `meta.sample_cap` 声明，切到全图（878）走独立请求——**上限该定多少属于产品/算法决策，不在本页自行拍板**。
3. **季度切片是结构演示，不是真实成长轨迹**。真实面板每企业中位观测 2 个月，做不出季度粒度；季度数据接上后本页才谈得上"成长轨迹"。
4. **中心性只在全量图上算**。抽样后的 `node_index` 百分位是**全图口径**（每个节点在全图中的排名），所以抽样图里"重要"与"看起来大"可能不一致——这是对的，页面已有说明。
5. **P6 前瞻预测、P7 单企业深度诊断仍是占位页**，等 FE-13 / FE-14。
