## 二、六区块交付明细

### 一 · 档案头部（`enterprise/detail`）

- **匿名徽标 + 匿名说明条**：`匿名企业 u0001` 旁边挂 `匿名态` chip，下方一条说明写明「userid→企业名映射键（P0-1）未到位，存档仅以匿名编号呈现；映射键补齐后此字段由后端填真实企业名，前端零改动」。**不隐藏、不美化、不编名字。**
- **缺失字段**：行业 / 成立年份显示 `未接入`（`MISSING_TEXT`），并带 `data-missing` 属性方便断言。**不写「未知」**——「未知」暗示查过但查不到，「未接入」说明这一列还没接。
- **观测月数**：`4 个月` + 厚度提示（< 3 个月标「薄」）；真实面板企业级中位约 2 个月，这个数是**占位随访窗**，写在下方的 `depth-note` 里。
- **企业切换器**：`<select>` 列出队列 12 家，切人只改路由参数并发新请求，**不改写页面结构**。请求的 `userid` 不在队列里时给出 `StatePanel`（"队列里没有 uXXXX"），而不是悄悄换成第一家。

### 二 · A18 信用评分仪表盘

- ECharts `gauge`（`startAngle: 200 / endAngle: -20`，`splitNumber: 5`，指针 + 进度环）。
- **五档色带由契约切点算出**，不是写死的五段等分：`bandCuts([50,60,70,80])` → 高风险 0–49 / 预警 50–59 / 关注 60–69 / 较好 70–79 / 优良 80–100，图例逐个给出区间端点。
- 三张卡：信用分、PD（相对口径）、档位序数（取 `RISK_BANDS[].band`，不按 `lo/20` 推）。
- 右下「这个分数能说明什么」：直接引用契约 `prior.auc_note`（行级实测 AUC≈0.599 vs 噪声地板 0.477），**把「这个分数只够排序、不构成放贷依据」摆在卡片正下方**。

### 三 · A19 特征雷达

- 3 维 × 4 项 = 12 根轴，双多边形：本企业（红实线 + 12% 填充）、同行中位（蓝虚线）。
- **缺数据维度给 `null` 而不是 0**：ECharts 对 `null` 不连线，图面留缺口；轴名后缀「（无数据）」；下方 chip 逐维标「n / 4 项有数据」；有缺维度时再出一条 `radar__warn` 说明缺哪几维、等哪个前置。
- 右侧 12 行明细表：本企业分位 / 同行中位 / 差值（正红负蓝），`无数据` 行整行置灰。
- 维度配色按 `factor_id`（tech / growth / fusion）取，不按中文名取——中文名一改，按名取色的图例会静默退化成灰。

### 四 · A20 SHAP 瀑布

- **22 段**：`E[f(x)]` 一根灰柱 → 20 个特征台阶 → `f(x)` 一根黑柱；台阶之间用 custom 系列画虚线连接，`yAxis.min/max` 由分段范围显式给死。
- **可加性摆在明面上**：图上方常驻 `Σφ（0.3339）+ E[f(x)]（-1.9788）= f(x)（-1.6449）`。
- 配平失败时**不画图**：`waterfallSegments()` 抛错 → 区块显示 `p7-waterfall-broken`（「这张图不可信」），而不是把图硬画出来。
- 两种排序：按 `|φ|`（默认）/ 按贡献方向（推高在前）；切换只改排序、不改数据。
- 明细表 20 行：`#` / 字段（`UnknownFieldTag`）/ φ / 相对幅度条 / 本企业方向 / 全局方向 / 本地vs全局（同向、反向）。

### 五 · A14 局部子图高亮

- `layout: 'none'` 手工坐标：中心节点（企业）+ 环状排布的一跳邻居（半径 220，纵向压 0.72 防止标签互压）。
- 边标签写中文关系（申请 / 授权 / 投资 / 任职 / 归属领域 / 产出产品），图例实时统计各实体类数量。
- **来源标注 `synthetic_graph`**：角标 + 区块底部说明都写明「邻居取自六类实体合成图，真实共现关系待 P0-4 / P0-5」。

### 六 · A14 时序贡献热力图

- 4 行（Top-4 特征）× 观测月，每格 = 该特征总贡献 × 当月分摊比例。
- **两条断言式约束**：每行分摊比例和 = 1（±1e-3 否则抛错）、每行格值之和 = 该特征总贡献。破了就不画，避免「热力图讲的故事和瀑布图相反」。
- 着色用**行内相对强度**（否则 0.11 与 0.017 差 6 倍，后三行会糊成一片浅色），格内标签仍是**绝对贡献**；图例写成「该行最强月 / 最弱月」。
- 观测窗高于真实中位数 + 2 时，出一条 `p7-heat-placeholder` 提醒「这些月份是占位随访窗」。

## 三、接口与契约

### 3.1 两份新契约与实测数据的锚定关系

`scripts/build_enterprise_contracts.py --all` 生成 4 份文件（主契约 + 两个降级态）：

| 契约 | `meta.source` | `contract_status` | 锚定了什么 |
| --- | --- | --- | --- |
| `enterprise_detail.json`（16.6 KB） | `contract_spec` | `mock` | 12 家 = 真实面板的观测企业数；阶段 / 同行家数按 `stage_factor_weight.json`；`prior` 里的噪声地板 0.477、行级 AUC 0.599 是**实测值** |
| `shap_local.json`（180.4 KB） | `reconstructed_from_anchors` | `mock` | 20 个字段、`mean|SHAP|`、`direction` 全部来自实测 `shap_global.json`；邻居来自 `graph_structure.json`（合成图）；逐企业幅度是**重建值** |
| `*_sparse.json` | `measured` | `partial` | 真实面板接上但技术要素 / 成长轨迹字段缺失时的降级态 |
| `*_label_pending.json` | `measured` | `partial` | label 口径（P0-3）未定时的降级态：只给档案，不给归因 |

### 3.2 三条链的自洽（都由脚本与冒烟双重把关）

| 链 | 约束 | 怎么验 |
| --- | --- | --- |
| 瀑布可加性 | `Σφ + E[f(x)] = f(x)`（log-odds） | 生成时 `abs(...) > 1e-3` → `SystemExit`；冒烟对 12 家逐一复核 |
| 时序守恒 | 每行 `Σby_month = 1`，行合计 = 该特征 φ | `heatCells()` 抛错 + 冒烟「每行格子之和 = 该特征总贡献」 |
| 局部 vs 全局 | ① 头号因子必须落在实测全局前三 ② 局部前五与全局前五至少重合 2 项 ③ 方向一致率 ≥ 0.35 | 生成时三条全查；冒烟再查一遍 |

**关于「局部 vs 全局」这一条，返工过两轮，值得写清楚**：

- 第一版用「逐企业 `mean|φ|` 与实测 `mean|SHAP|` 的秩相关 ≥ 0.9」当门槛。结果是：任何一个企业在尾部有 2~3 项翻号（局部解释的正常现象），Spearman 就掉到 0.4~0.7，门槛逼着脚本把每家企业都做成「全局排序的等比缩放」——那不是局部解释，是全局图的复读。
- 更糟的是为了过门槛，`v` 被写成 `along = 1 + 噪声`（恒正），于是**无论哪家企业、多少分，20 根柱子清一色朝上**：图能画、等式也配平，但那张图在业务上没有任何信息量。
- 现在改成「水平项 + 零和个体项」的分解：`φ_j = target·w_j/W + w_j·a_j`，`Σw·a = 0` 由构造保证，个体项幅度随排名放大（头部稳、尾部容易翻号）。可加性变成**构造出来的**，不再靠事后平移配平。
- 现在的数值：`ρ` 从 0.38 到 0.78（只作参考指标写进契约，不作门槛），头号因子 12/12 命中全局前三，前五重合最少 2 项，方向一致率 0.40~0.70。

### 3.3 确定性

固定 `seed = 20261087` + 自写 LCG（不依赖 numpy），同一个 seed 跑两次字节级一致。没有任何 `random` / 时间戳参与数值生成（`generated_at` 除外）。

| 红线 | 本页怎么落 | 反例（本页刻意不做的） |

## 五、取数纪律与降级

### 5.1 两层守卫

1. **信封层**（`isEnvelope`）：`code === 0` + `data` 存在 + `meta.dataset / schema_version` 齐；
2. **结构层**（视图内 `pick` / `hasShape`）：`enterprises` 非空、`risk_bands.cuts` 四段、`radar` 三维、`entries` 里能按当前 `userid` 找到人。

任一层不过 → 该区块走 `StatePanel`，**另一块照常出图**（详情与局部归因是两个独立 `useAsyncSection`）。

### 5.2 降级边界

- 档案打空 → 页头保留、档案以下全部换成「企业档案未能加载」（原因 + 下一步 + 重新取数）。
- 档案有、局部归因打空 → 瀑布 / 图谱 / 热力图三块各自降级，档案与评分照常。
- 两个都打空 → 页头 + 降级面板 + **读图问答仍在**（正文 1221 字，0 报错）。
  「读图问答」这一块被特意移到了 `v-else` 之外——降级时读者最需要的就是「这页本来能回答什么」。
- `LABEL_PENDING` 是**阻塞态**，不是「暂无数据」：`contract_status: 'label_pending'` 时降级文案直接点名「后端返回 LABEL_PENDING」。

### 5.3 几个不显眼但会咬人的实现细节

| 坑 | 表现 | 现在怎么做 |
| --- | --- | --- |
| custom 系列不回传自定义字段 | `params.data.seg` 抛 `Cannot read properties of undefined` → 整页被 `onErrorCaptured` 接走变错误态 | `renderItem` 只读 `params.dataIndex`，从闭包取分段 |
| custom 的 `value` 不参与轴极值 | 轴域 0…1，所有柱子被裁掉，既不报错也不是白图 | `yAxis.min/max` 由 `axisRange(segs)` 显式给死 |
| custom 系列不支持 `markLine` | 整条 series 判为非法、图元静默不画 | 参考虚线改成第三条 custom 系列自己画 |
| 单值 data 的 `dataIndex` 恒为 0 | 22 根柱子全叠在最后一列 | `data` 给 `[序号, 数值]`，`xAxis.data` 给 `[0..n-1]` |

## 九、已知限制与后续

1. **语义全是占位**。20 个归因字段、12 个雷达指标、全部邻居标签都还没有业务名。P0-2（`x21–x200` 字段字典）到位后，只需把 `label_ref` 指向字典，页面零改动。
2. **基线口径**。`E[f(x)]` 取的是 12 家匿名队列的均值 log-odds（与 f(x) 同口径）。真实 backend 落盘 SHOULD 用它自己的背景数据集均值；届时契约里 `prior.queue_mean_*` 会被替换，前端仍读 `base_value`。
3. **PD 未校准**。分数→PD 是 `logistic((score-62)/6.2)` 的占位映射，只保证单调，没有经过 label 口径校准（P0-3）。页面上写死「不是校准后的违约概率」。
4. **邻居是合成图**。真实共现关系要等 P0-4（专利授权）与 P0-5（投资 / 工商变更）。
5. **观测窗是占位**。真实面板企业级中位约 2 个月观测，本页给了 4–9 个月用于验证「跨月切片」的交互，热力图会自己标出来。
6. **单企业 AUC 无意义**。行级 AUC 0.599 与噪声地板 0.477 只差 0.1，这一页的分数**只够排序**；真正的判别力评估在 P4 / P5。
7. **P8 批量评估未交付**。页脚已写明「批量评估（P8）待交付，届时从本页可直接跳转『把这家企业加入批量任务』」。

## 附：一句话给评审

> 这一页把「一家企业为什么是这个分数」拆成六步：它是谁（档案）→ 多少分（仪表盘）→ 偏在哪（雷达）→ 谁推的（瀑布）→ 它连了谁（局部图谱）→ 什么时候变的（时序）。
> 每一步的数字都能追到契约里的同一个 `userid`，每一步缺数据时都明说缺什么、等哪个前置，而不是画一个 0 或者编一个名字。
